# CONSTRAINTS — django-pytest

Each constraint is tagged: [HARD] enforced by tooling/config, [SOFT] convention,
[EXTERNAL] imposed by an upstream/ecosystem rule, [UNKNOWN] not determinable.

## Technical

- [HARD] Python `>=3.14` is the packaged floor (`pyproject.toml requires-python`).
  Code reportedly runs on 3.11+ (CLAUDE.md/README) but the distribution requires 3.14.
- [HARD] Runtime deps floor: `django>=6.1`, `pytest>=9.1.1` (`pyproject.toml`).
- [HARD] The self-suite must not self-activate the plugin: `addopts` carries
  `-p no:django_pytest` and `-p no:query_optimizer` (`pyproject.toml`).
- [HARD] Coverage gate `fail_under = 80` (`pyproject.toml`).
- [HARD] Lint: ruff line-length 120, double quotes, single-line isort,
  `lines-after-imports = 2`; `E501` and `ANN401` ignored (`pyproject.toml`).
- [HARD] mypy strict, with two strict sub-checks relaxed because Django base
  classes are untyped for a settings-less reusable app, and `[method-assign]`
  disabled for the deliberate `admin.site.get_urls` monkey-patch (`pyproject.toml`).
- [SOFT] ruff `target-version` pinned to py313 (not py314) because ruff format
  ≤0.15.15 strips multi-except parens under py314 — a temporary workaround noted
  in `pyproject.toml` to restore when fixed upstream.
- [HARD] The analysis engine imports neither Django nor pytest (ADR-001 invariant;
  keeps it unit-testable). Enforced by convention/review, not an automated test.

## Architectural / design

- [SOFT] One class per file; import the item not the module; named-argument call
  sites (CLAUDE.md → chrysa backend-python rules).
- [SOFT] Test files named `tests_*.py` (CLAUDE.md).
- [HARD] Package uses `src/` layout; tests run with `pythonpath = [".", "src"]`.

## Ecosystem / governance [EXTERNAL]

- Depends on `shared-standards` (canon); where an annexe and canon disagree, canon
  wins (CLAUDE.md, `standards/`).
- Conventional Commits enforced via `conventional-pre-commit`; typed branch
  prefixes required; direct commits to a protected branch blocked (CONTRIBUTING.md,
  `.pre-commit-config.yaml`).
- Generated context files (`handover.md`, `ai-instructions.md`, `context-map.json`,
  `llms-full.txt`) are generated by `scripts/gen_context_files.py` (ADR D-0012) —
  do not hand-edit. Note: the regeneration target named in those files
  (`make gen-context-files`) is **not present in the current Makefile** — see REVIEW.md.
- Container-first: CI runs the suite via `Dockerfile.test` (chrysa containers rule).
